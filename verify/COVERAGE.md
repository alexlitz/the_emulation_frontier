## Definitions

- **M1** types whose code diff vs parent is fully classified (every hunk carrying the type has a label) / every model type in the snapshot with code; types with no code anywhere are the plan's stated exclusion, counted in the detail.
- **M2** feature variants with read ∧ (host branch ∨ wall) ∧ rule as target ∧ rule as host / every variant in the sweep's coverage matrix (verify/sweep/coverage.json).
- **M3** allowed headline rules with a Lean theorem or a recorded measurement / all allowed headline rules, from EDGE_JUSTIFICATION.md (generated from the code by verify/z3_relation.py). With the verdict column (z3-final on): rules whose modes include payable (the headline relation), over the slot, ZERO_EDGES, feature and capacity tables; justified = verdict PROVED or MEASURED (UNJUSTIFIED and REFUTED are not). The older format without verdicts: slot transitions + capacity rules, justified if the theorem column names a theorem and the note does not say REFUTED.
- **M4** walls labelled proved-impossible (or another PROVED / REFUTED status) or OPEN with a measurement / all walls in PROOFS.md's walls table.
- **M5** construction theorems with a test on the repo function that builds them (BRIDGES.md BRIDGED rows) / all construction theorems: the Lean library's `theorem` declarations (lemmas are helpers) minus the ones BRIDGES.md lists as not counted (helpers, impossibility theorems, negative controls).
- **M6** headline reduction types with a non-skipped catalog test that builds and verifies / every headline type of verify/spot/reduction_types.json. Runs tests/test_reduction_catalog.py -m "not slow" (the synthetic entries; the meta-test requires one per type) and maps each passing entry to its types through verify.spot.catalog.CATALOG.
- **M7** spot-checked edges passing / sampled (verify/spot/results.jsonl; the plan asks >= 200, stratified).
- **M8** headline edges (shape pairs, j != i, emul_matrix(mode='payable')) that elephantine.emulate v1 builds for the shapes' command repos (graph.edge_plan.cmd_repo; exact edge, both sides supported, support() is None) / all headline edges. The counting of graph.model_graph.zoo_data / graph.edge_plan.zoo_edges, over every edge.
- **M9** real ordered shape pairs x modes x flag sets where the Z3 model equals emul_matrix / all of them: the differential check of verify/z3_relation.py, cached in verify/z3_results.json by --run-z3, else read from EDGE_JUSTIFICATION.md's properties section (pairs = shapes x (shapes + the joined host) x modes x flags).
- **M10** {reflexive, transitive, monotone, join} x 4 modes proved by Z3 on the final code / 16. Monotone for mode m is exact <= payable <= mixgap <= capacity at the link from m; for capacity (the top) every link.
- **M11** models whose family loader runs against its own code (graph.minimal_emulator.loaded_split: loaded and tested) / all models in the snapshot (graph.minimal_emulator.load).
- **M12** limit rules (PROOFS.md 'Every allowed rule' rows whose status is a limit or a bound) with a per-op bound, a whole-model bound, a greedy threshold and measured or derived constants / all limit rules. The parts are found by theorem name: a row's theorems, and for each stem X (a theorem name minus _bound / _limit / _greedy, a_sub_b -> a_b) the library's X_bound / X_layer_bound, X_model_bound / X_model_limit, X_greedy.
- **M13** page features with an automated browser test / all page features. The page template declares its features, as data-feature="name" attributes or one comment <!-- zoo-features: a, b, c -->; a feature is tested if tests/test_zoo_browser.py names it in a string literal.
- **M14** draft numbers matching the computed values / every number the strict checker sees in the draft: the agreeing occurrences, over agreeing + mismatching occurrences + uncovered numbers + missing anchors (graph/check_post.py; --strict fails on a missing anchor). The draft is only read.
- **M15** confirmed bugs with a passing regression test / all confirmed bugs in tests/test_review_findings.py. Static: a bug is fixed when none of its tests carries the xfail(strict=True) marker (strict mode makes a fixed bug's marker fail, so the marker goes with the fix). A test's bug number is its section comment '# --- N.', or 'REVIEW N' in its xfail reason.
