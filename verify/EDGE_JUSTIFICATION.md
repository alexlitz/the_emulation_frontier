Generated by `python -m verify.z3_relation --edges` (verify/edge_table.py) from `graph.model_graph`: the slot transitions are enumerated from `slot_reaches` / `regime_reaches` with the strictness `emul_matrix` derives per mode (as the Z3 model's tables are), decomposed into the order's hops; the ZERO_EDGES; every feature a host may lack or carry (`feats_ok` on one-feature sets); and the capacity rules, one or more per numeric conjunct of `emul_matrix` (`verify/z3_relation.py` Model.parts). Theorem names: `proofs/PROOFS.md` (Lean 4 + Mathlib, namespace EP); every name is checked against the Lean sources.

Verdicts: **PROVED** (a theorem covers the rule as the relation uses it; kind exact / limit / bound / regime), **CODE** (the host's own code path, no construction: a null config value, an identical layer), **CATALOG** (verified instance (catalog), theorem pending: an end-to-end instance in the reduction catalog builds and checks the rule, its one-line theorem is not written yet -- not counted as proved), **MEASURED** (an approximate edge whose payability is a recorded measurement), **REFUTED** (a theorem proves the rule false as used), **UNJUSTIFIED** (nothing). A *headline* rule is one the payable relation allows. `real edges` counts ordered pairs of the 942 real shapes in the exact / payable / mixgap matrix whose values are that transition (a capacity rule: whose pair uses it). `capacity` mode ignores every slot but gen and is not listed per row. Transitions into the abstract tops (AffineNorm, pos_top, act_top) and branch sets are omitted.
