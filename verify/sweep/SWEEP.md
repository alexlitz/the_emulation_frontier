## Conventions and caveats

- The reference forward is the eager attention path in fp32 on fixed weights, text-only input. Flash / sdpa subclasses (rule:backend), float32 upcasts and dtype casts of constants are IRRELEVANT on that basis; `sliding_window_backend_dependent` records the one case where the default sdpa backend differs from eager.
- rule:unreached is static: a class or method no causal-LM entry class can reach by name (attribute access, constructor, module function) never runs. Over-inclusive by design (any attribute of the same name reaches), so it can only under-prune.
- rule:config_default_unused uses the snapshot: a class default every config of the type overrides never runs. A future config that omits the key needs a re-sweep (the test fails on a new type, not on a new config of a known type).
- Several IRRELEVANT review labels are snapshot-dependent (code paths no current config switches on: Nanbeige hyper-connections, MiniCPM InfLLM-v2 sparse attention, MemT memory, ...); the review reason says so.
- The models column counts the carriers of the code (every snapshot model whose type or remote variant contains the hunk). Where a finding needs a config path (e.g. Gemma-4 enable_moe_block), the models that take that path are a subset; the reasons in findings.json name them.
- Hunk ids are hashes of (role, member, changed lines): the same edit in many files is one hunk, classified once. hunks.jsonl keeps a stub of the text for rule-decided hunks; `python verify/sweep/sweep.py` regenerates the full hunks (hunks_raw.jsonl, not committed).
