The emulation zoo

Every decoder LM on the Hub, by size and by how many models it can emulate, with a spec sheet per shape. Companion to The Emulation Frontier.

Model A emulates model B when some setting of A's weights makes A compute exactly what B computes, or within a measured, priced error. Every decoder language model in a snapshot of the Hugging Face Hub is placed below by its size and by how many models it can emulate. Repos with the same architecture and size collapse into one shape. The frontier is the set of shapes that no other model emulates; between them they emulate every model here.

It is also a spec sheet for every one of those shapes, read the way its modelling code runs it, not only from its config: where the norms sit, which qk-norm, the sliding / global and NoPE layer schedule, K = V, the MoE router, MLA latents. Open the Models table, Compare up to four, or see when each feature first appeared on the Timeline. Press / to search and 1–8 for the views.

    Glossary

    Any Hugging Face model

    computed in your browser from its config.json

    The page fetches config.json from huggingface.co (public repos only: a gated or private repo cannot be read from a browser without your login) and runs the same formulas as the zoo's metrics pass (graph/arch_metrics.py, ported to JavaScript and checked equal on all the snapshot configs). The numbers are formula only: no trace check ran on this config.

    Reading the numbers

    Cover: how many of the snapshot's models a shape emulates, its own repos included. Emulated by: how many models in other shapes emulate it. A shape is one architecture at one size; fine-tunes, quantizations and re-uploads of it share a node.

    ≈ Params is for placement only: the Hugging Face safetensors count where a full-precision member has one, else the size in the repo name, else an estimate from the config. It is not part of the relation.

    Why a shape is on the frontier

    RECORD: it holds the largest value of some capacity axis. WALL: a bigger model dominates it on capacity, but a type difference with no known way to pay for it (an activation, a positional scheme, a recurrent mixer) stops that model emulating it. PARETO: maximal through a trade-off between capacities. PARADIGM: a diffusion model; diffusion hosts emulate autoregressive models, never the reverse.

    Where the specs come from

    Each card is the shape's most-downloaded repo as graph/model_graph.py reads it (classify, dims_of and the per-type tables of facts read from the modelling code). A code mark is a value one of those tables set rather than a config key. Lineage and code links come from the code-diff sweep (verify/sweep/inventory.json), and so do the notes on where code and classifier disagree. Dates and parameter counts are the Hub's: the repo's creation date and its safetensors total. A field the sources do not give is left blank.
